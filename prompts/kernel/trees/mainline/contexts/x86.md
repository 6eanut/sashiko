# x86 Subsystem Code Context Guide (Linux v7.3-rc5)

This guide provides architectural invariants and bug-prevention rules for the `arch/x86/` subsystem, specifically tailored for the Linux v7.3-rc5 kernel.

## 1. Subsystem Architecture, Core Data Structures & Object Lifetimes
*   **Per-CPU State:** The `struct pcpu_hot` and `struct cpu_entry_area` are the primary anchors for per-CPU state. Accessing these requires strict preemption disabling (`preempt_disable()`) or execution in an atomic context where migration is impossible.
*   **Feature Detection:** Use `cpu_feature_enabled(X86_FEATURE_*)` for runtime checks. Avoid `boot_cpu_has()` in hot paths; `cpu_feature_enabled` uses static keys for zero-overhead branching.
*   **Object Lifetimes:** Objects associated with `struct device` must follow the `get_device()`/`put_device()` lifecycle. Always validate with `has_acpi_companion(dev)`.
*   **Task Migration:** Operations modifying per-CPU hardware registers (e.g., `wrmsrl`, `rdmsrl`) must be protected against task migration. Use `get_cpu_var()` or `preempt_disable()` to pin the task to the current core.

## 2. Synchronization Model, Lock Hierarchy & Concurrency Rules
*   **Locking Hierarchy:**
    *   `text_mutex` must be held when modifying kernel code via `text_poke`.
    *   `pgd_lock` or `mm->page_table_lock` must be held when modifying page tables.
    *   **Rule:** Never perform blocking operations (e.g., `kmalloc(GFP_KERNEL)`, `mutex_lock`) inside `text_poke`, `__kprobes` functions, or exception handlers.
*   **RCU:** When traversing lockless lists, `rcu_read_lock()` is mandatory. Use `rcu_dereference()` to access pointers to ensure visibility.
*   **Atomic Contexts:** Ensure that all per-CPU data accesses spanning multiple instructions are protected by `preempt_disable()` to prevent migration-induced data corruption.

## 3. Initialization, Registration & Teardown
*   **Premature Publication:** A subsystem must never register its interface (e.g., `perf_pmu_register`, `sysfs_create_group`) until all internal state, global pointers, and hardware constraints are fully initialized.
*   **Error Unwind:** Use the "goto-label" pattern for symmetric cleanup. If a resource allocation succeeds but a subsequent one fails, the error path must invoke the corresponding release function for all previously allocated resources.
*   **Exported Symbols:** Any function exported via `EXPORT_SYMBOL_GPL` must check the global initialization state to prevent NULL pointer dereferences.
*   **Initialization Audits:** Periodically audit initialization routines to remove references to legacy data structures no longer used by the hardware.

## 4. Error Handling, Resource Recovery & Boundary Validation
*   **IS_ERR vs NULL:** Always use `IS_ERR()` to check return values from kernel APIs. A non-NULL pointer is not necessarily a valid pointer. Use signed types to store return values that can represent both valid IDs and error codes.
*   **Integer Overflow:** When calculating buffer sizes for `kmalloc` or `vmalloc` based on user-provided lengths, use `size_mul()`, `size_add()`, or `check_add_overflow()` to prevent wrap-around.
*   **Pointer Arithmetic:** Ensure all pointer arithmetic is bounds-checked against the allocated object size. Use `struct_size()` and `array_size()` for dynamic allocations.
*   **Error Propagation:** Ensure error codes are correctly propagated up the call stack without being masked by subsequent cleanup operations.

## 5. Hardware, DMA, Power & Bus Protocol
*   **Register Access:**
    *   Use `wrmsrl()` and `rdmsrl()` for MSRs.
    *   **Masking:** Always mask MSR writes with allowed bits to prevent setting reserved bits (e.g., `PERF_GLOBAL_CTRL`).
    *   **Feature Isolation:** Do not write to hardware registers if the feature is not active (e.g., check `PEBS_ENABLED` before modifying PEBS MSRs).
*   **Instruction Patching:** When using `text_poke`, ensure the target memory is not concurrently modified by page attribute changes. Use `text_mutex` to serialize.
*   **DMA:** When using IOMMU, ensure DMA attributes are correctly applied.
*   **Event Constraints:** PEBS/PMU event constraints must be strictly limited to documented hardware. Validate that all required event flags are set for hardware events performing direction-sensitive sampling.

## 6. High-Frequency Bug Patterns & False-Positive Guards
*   **Pattern: Sleeping in Atomic Context.**
    *   *Guard:* Flag any `mutex_lock`, `msleep`, or `GFP_KERNEL` allocation inside functions marked `__kprobes` or called from `perf` event callbacks.
*   **Pattern: Unbalanced Refcount.**
    *   *Guard:* Every `get_device()` or `pci_dev_get()` must have a corresponding `put_device()` or `pci_dev_put()` on all exit paths.
*   **Pattern: Stale Pointer Dereference.**
    *   *Guard:* Ensure that `fwnode` pointers are updated when the underlying physical device is detached or re-probed.

## 7. Critical Invariants for v7.3-rc5
*   **FRED (Flexible Return and Event Delivery):** Exception handlers must correctly reconstruct the instruction pointer and error codes. Any patch modifying `arch/x86/entry/entry_64.S` or `arch/x86/kernel/fred.c` must be audited for ABI compliance.
*   **Page Table Modifications:** When using `pmd_modify` or similar, ensure hardware-defined status bits (e.g., Dirty, Accessed) are preserved. Use standard page table allocation helpers to ensure metadata and accounting are initialized.
*   **Symbolic Constants:** Never use hardcoded magic numbers for instruction offsets or register bits. Use defined macros (e.g., `X86_FEATURE_*`, `MSR_*`).
*   **Instruction Patching:** Ensure the patching mechanism correctly identifies and handles segment-prefixed instructions to avoid invalid memory access.
